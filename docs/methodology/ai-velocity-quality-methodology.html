§0 · TL;DR

一页纸结论

问题不是「review 跟不上」,而是用线性人工流程去对抗指数级生成产能,且人工 review 恰好抓不住 AI 代码的典型缺陷。任何「审得更快/更多/招更多人」都是在错误维度上加码。

§1 · 问题定义

三个结构性不对称

现象是「review 来不及 / 草率 merge → 深层问题潜伏渗透」。但现象不是根因。根因是三个不对称,它们决定了为什么传统手段必然失败。

1.1 产能不对称 · 生成 O(海量) vs 人工验证 O(线性)
试图用扩充人力追平指数曲线——数学上注定输。这条不对称证伪了一切「在 review 吞吐维度上加码」的方案。
AI 生成产能

线性 · 昂贵 · 会疲劳
1.2 缺陷类型不对称 · AI 缺陷骗过人类依赖的信号
人工 review 依赖表层信号(能编译、读着顺、过测试、风格像)。AI 产出恰好在这些信号上优异,却可能违反不变量 / 跨 repo 契约 / 规格语义——人眼逐行本就抓不住。

wallet tx 编码须与 node 字节级一致;CIP 接口横跨 node+runner+cbfs。最致命的破坏发生在跨边界——任何单 repo 的 CI、单个 reviewer 在设计上就看不到。

→ 推论

根因是结构性的,解法也必须结构性:改变验证的执行主体(人→机器)、改变注意力分配(全部→分级)、改变系统的学习方式(一次性→棘轮)。下文三支柱逐一对应。

§2 · 第一性原理

设计哲学

后续每个机制都是这四条原则的推论。

01

能写成断言的,就不该靠人 review

机器检查不睡觉、不疲劳、不被漂亮 diff 蒙骗,且对未来所有 PR 永久生效。把一次性 review 成本转化为永久复利的资产。

02

人类注意力是最稀缺资源,只投在不可替代的判断上

架构取舍、CIP 意图、新不变量的发现——AI 暂时替代不了。逐行看 AI 写的样板代码不是。

03

承认 pre-merge 永不完美,所以纵深防御

不追求一道门挡住一切,而是多层网,让逃逸在 devnet(而非主网/用户)被抓住。

04

系统必须从每次失败中变得更聪明

没有棘轮的质量体系会随时间退化;有棘轮的会随时间收紧。这是唯一能跟上指数产能的机制——因为它也是复利的。

支柱 1 · 最高杠杆

可执行的不变量门禁

那些「潜伏极深、本质性」的 bug,绝大多数是某条没被任何地方编码、因此无法被检查的不变量被违反了。把它写成机器每次都跑的检查,就一次性把 review 负担转成 CI 门禁。

Cowboy 不变量族(落地种子)

💰

经济 / Gas 守恒

burn+tip==fee_total;escrow 永不为负;dual-meter 计量与实际操作一致;settlement 三方比例之和恒为 100%。→ 用 proptest,而非逐行审 verifier.rs。

🔗

跨 repo 契约(打击 §1.3 盲区)

wallet 编码 → node 解出完全相同字节。维护 golden vectors 放进双方 CI;任一侧破坏立即红灯。

🐍

PVM 确定性

validate_actor_code() + determinism harness 持续加厚。已知逃逸:bare literal 2**10000 绕过 INT_GUARD_PREAMBLE → 棘轮盯死项。

⛓️

状态 / 共识

nonce 单调;Merkle root 三阶段一致;speculative rollback 后状态等价。

⭐ 判定标准

凡是一个缺陷「本可被一条断言抓住」,它就不该进入人工 review 的职责范围。单测验证「具体输入→具体输出」;不变量验证「对所有输入某性质恒成立」——AI 最易写出过单测却违反全局性质的代码,这正是要补的层。

支柱 2 · 注意力分配

风险分级的注意力分配

不是所有 PR 值得同等审查。用 AI 自动给每个 PR 打爆炸半径标签并路由,把稀缺的人类注意力集中到高危处。

高危
  • 共识 / execution / gas
  • crypto / state-root
  • 跨 repo 契约
  • CIP 定义接口
深审 + /code-review ultra 多 agent + ≥1 领域 owner 签字 + merge queue
中危
  • 普通 actor 逻辑
  • RPC handler
  • 非契约型 runner 代码
AI 对抗式 review + 1 名人工 review
低危
  • 文档
  • 测试
  • 工具脚本 / 注释
AI review 通过即可,人工抽查

两条配套硬约束 从源头降成本

📏

小 PR 强制

AI 倾向产出庞大 diff,而庞大 diff 不可审。拒绝 mega-PR,一个 PR 一个关注点——降低单次 review 成本最有效的手段。

🧭

高危先设计后写码

架构 / CIP 级改动先走 brainstorming / 设计评审再写代码。否则你在审一个建立在错误前提上的 2000 行实现——把判断点前移,成本低一个数量级。

支柱 3 · 复利来源

逃逸即学习的棘轮

每发现一个「潜伏很深」的 bug,强制做轻量 post-mortem,产出至少一条永久检查:回归测试、新不变量(回流支柱 1)、lint、或 review agent prompt 规则。

⚙️ 为什么是复利来源

你被咬过的地方,网就在那里织得更密,同类问题再不可能静默通过。这是整个体系唯一能「随时间收紧而非退化」的机制。

关键纪律

🌱

prompt 从真实逃逸生长

audit-bot 维度 agent 的每条 prompt 规则都应能追溯到一次真实逃逸,而非凭空设计。

✅

产物是检查,不是文档

没人会再读的事后分析不构成棘轮;一条永久运行的断言才构成。

📒

维护逃逸登记册

记录每次逃逸 + 织出的那条检查。既是复盘资产,也是「网在哪里收紧」的度量依据。

包裹 A · 连接三支柱

AI 对抗式 review 层

把自研的 audit-bot(5 维度 agent)和平台的 /code-review ultra 正式做成 PR gate,喂给支柱 2 的分级。

⚠️ 致命陷阱:相关性盲区

AI 审 AI 有相关性盲区——同源模型会在同样的地方一起瞎,给你「全绿」的虚假安心。这比没有 review 更危险,因为它制造了已审查的错觉。

架构上强制三条

🗡️

对抗式而非背书式

prompt 是「找出这个改动会怎样出错 / 违反哪条 CIP 不变量」,默认怀疑,而非「看起来还行吗」。

🎭

视角多样化

多 agent 用不同视角:正确性 / 规格符合 / 跨 repo 契约 / 安全 / 经济 / 确定性。靠分歧和 quorum 标记问题——冗余同视角抓不到多样失败。

📋

结构化输出,不替代终审

输出「发现+严重度+置信度」喂给分级路由。作用是扩大覆盖面、抬高地板、帮人聚焦,不替高危改动签字。

§5 · 优先级最高的杠杆面

CIP 规格层治理

规格是放大器:一个有缺陷的 CIP 会复制进多个实现,危害指数放大。所以规格层门禁优先级高于代码层。

🗺️

1 · CIP 改动必须附结构化影响分析

动了哪些不变量、影响哪些 crate/repo、兼容性/迁移、安全含义。AI 极擅长这种 fan-out——让它生成初稿,人只审这张「影响地图」,比审所有相关代码便宜得多。

📊

2 · 维护 conformance matrix

每条 CIP 要求 → 验证它的测试。gap 一目了然。与 refs/wiki/drift.md 漂移看板联动。

🚧

3 · 硬门禁

CIP 不能 merge,直到其 conformance 测试存在(或显式 waive 并记录原因+责任人)。把规格和验证强绑定,杜绝静默漂移。

包裹 B · 安全网

运行时纵深防御

承认 pre-merge 永远不完美,深层 bug 一定会漏过。目标是在它渗透到主网 / 用户之前抓住。

🧪

devnet 常驻校验

fuzzing / 不变量断言 / 差分重放(对照参考实现)。把支柱 1 的不变量也部署成运行时断言,而不只是 CI 测试。

⚖️

复用 CIP-2 运行时机制

dispute window(DISPUTE_WINDOW_BLOCKS=75)、verification modes(MajorityVote / Deterministic / EconomicBond)本身就是「运行时校验+经济惩罚」的纵深防御。扩展到执行层。

🐤

金丝雀 / 灰度

高危改动先在 devnet 跑足够长的真实负载(benchmark/ WindTunnel)再上推。

放进 cowpilot dashboard,作为方法论是否生效的客观信号,也是说服团队投入门禁建设的弹药。

§8 · 按杠杆排序

落地路线图

每一步都可独立交付价值,不必等全套就绪。

1

不变量门禁 + 逃逸棘轮(支柱 1+3)

最高复利,天然增量——从「已经被咬过的地方」开始织网(如 2**10000 逃逸、gas 守恒)。

2

风险分级路由 + 小 PR 约束(支柱 2)

立刻缓解「审不过来」。

3

对抗式 PR gate(包裹 A)

把 audit-bot / /code-review ultra 接成门禁,注意防相关性盲区。

4

CIP conformance matrix + 影响分析(§5)

规格层杠杆最大但需流程共识,放在团队对前几步有信心之后。

5

devnet 纵深防御 + 指标 dashboard

持续推进。

💡 建议

不要试图一次铺开全部。挑一个切入点先跑通闭环——推荐「跨 repo tx 编码 conformance vectors」(直击 §1.3 盲区)或「经济守恒 property tests」(支柱 1 最干净的样板)。跑通一个,团队就有了信心和模板。

§9 · 明确不要做什么

反模式清单

悬停查看为什么错。

✕ 招更多人 / 审得更快
在产能不对称的错误维度加码(§1.1)。
✕ 审得更细就能抓住深层 bug
人眼不擅长抓不变量/契约类缺陷,网型不对(§1.2)。
✕ 上了 AI reviewer 就放心了
相关性盲区制造虚假安心,比没审更危险(§4)。
✕ 只写 post-mortem 文档
没人再读的文档不是棘轮;只有永久检查才是(§3)。
✕ 先把全套体系建好再上线
违背增量交付;应挑一个切入点跑通闭环(§8)。
✕ CIP 先 merge,测试以后补
规格层是放大器,静默漂移危害指数级(§5)。
✕ 大 PR 一把梭
庞大 diff 不可审,AI 尤其爱产出(支柱 2)。

▸附录 A · 不变量种子清单(支柱 1 起点)点击展开
经济 / Gas
  • burn + tip == fee_total(每 tx / 每 block)
  • escrow_balance >= 0 恒成立(job_submit / settlement / cancel 全路径)
  • runner_percent + burn_percent + treasury_percent == 100(默认 89/10/1,已核验)
  • dual-meter:计费 Cells == 实际 key.len()+val.len() 累计;Cycles == 实际操作累计
  • basefee 更新单调性:EIP-1559 公式对 target 上/下偏离方向正确
状态 / 共识
  • account nonce 单调递增,无跳号
  • Merkle root 在 propose / verify / report 三阶段对同一 batch 恒等
  • speculative rollback 后状态 == 执行前状态(含嵌套 actor 调用)
  • deferred tx:pending_per_actor ≤ 64;age ≤ 1000 blocks(均已核验)
跨 repo 契约
  • wallet 编码 tx → node 解码字节级一致(golden vectors,双向)
  • runner 的 RateCard / RunnerResult / VerifierCheck 与 node/runner/src/types.rs 序列化兼容
  • CIP 定义接口的每个方法签名 + 语义 conformance
PVM 确定性
  • 黑名单 import(ctypes/_ctypes/cffi/_cffi_backend)被拒(已核验)
  • 大整数:int(2)**10000 被 guard 拦截;bare literal 2**10000 已知逃逸 → 棘轮盯死项
  • asyncio.gather ban;1234-digit int limit
  • 同 actor + 同输入 → 跨节点字节级相同输出
▸附录 B · 风险分级路由判定(支柱 2 实现要点)点击展开
判高危(命中任一)
  • 路径含 execution/{engine,transaction,system_instruction,basefee} / storage/{speculative,process_block} / chain/ 共识 / 任何 crypto / *_root 计算
  • 改动跨 ≥2 个 repo,或触碰跨 repo 契约文件
  • PR 关联 CIP 标签为「新增」或「接口变更」
  • 触碰系统 actor 地址逻辑(0x06/0x09/0x91–0x95;注:0x06 一址双用 Basefee+TokenRegistry,爆炸半径更大)

  • 普通 actor 逻辑、RPC handler、非契约型 runner 代码
判低危
  • 仅 *.md / 测试 / 脚本 / 注释
